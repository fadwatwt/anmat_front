# مراجعة أنظمة لوحة أنماط — 18 أكتوبر 2026

هذه المراجعة تغطي الشيفرة المحلية واختبارات آلية مع خدمات محاكاة. لا تُعدّ إثباتًا لاتصال مزودي الذكاء أو منصات التواصل بالحسابات الحقيقية، ولا تتضمن نشرًا على الخادم.

## الإصلاحات

- تحويل `/dashboard/ai`، الذي كان يولّد ردودًا تجريبية، إلى `/ai` الفعلي.
- إضافة مساعد ذكاء عام في الصفحة الخارجية يجيب عن معلومات أنماط عبر مسار عام مقيّد، مع تعريف صريح بأنه ذكاء اصطناعي وروابط واضحة للتسجيل والدعم.
- فصل تعليمات بوت الدعم عن تعليمات مساعد الأعمال، وقصر أدوات الدعم على البحث في قاعدة المعرفة. التحقق من نطاق الأدوات عند التنفيذ، لا عند عرضها للنموذج فقط.
- منع التصعيد التلقائي من وضع الدعم؛ واجهته تعرض ملخص الطلب وتنتظر تأكيد المستخدم.
- عزل عدّاد الاستهلاك لكل طلب متزامن، وإدراج استهلاك استجابة الاسترداد في الحساب.
- حفظ استدعاء الأداة قبل نتيجتها في سجل المحادثة لتوافق تسلسل الرسائل بين المزودين.
- رفض تكرار أسماء الأدوات عند التسجيل بدل استبدال أداة بأخرى بصمت.
- منع التحويل إلى مزود يستبدل المرفقات بعبارات نصية ولا يرسل محتواها الفعلي.
- إزالة حسابات فيسبوك التجريبية وأزرار الإجراءات الوهمية. توضيح عدم اتصال فيسبوك وإنستغرام وجيميل ويوتيوب.
- تمييز تعطل خدمة حسابات إكس عن حالة عدم وجود حسابات، وإضافة إعادة المحاولة.
- إصلاح عناوين تأكيد وإلغاء الإجراءات في خدمة الذكاء القديمة، وتمرير وضع المحادثة في واجهتي إرسال الرسائل.
- إصلاح عرض الشيفرة داخل الرسائل: اتجاه مستقل من اليسار إلى اليمين، بلا تداخل عناصر `pre`؛ وعزل أسماء النماذج ومعرّفات حسابات التواصل.
- تضمين القاموس العربي مع التطبيق، وإكمال المفاتيح الثابتة الناقصة وسجل النشاط وخطوات البدء، وتصحيح الاستيفاء النصي لأسماء الأدوار.
- توحيد رصيد الذكاء باسم «وحدات المعالجة»، وترجمة أوصاف النماذج، وتصحيح مصطلحات الدعم والحضور واسم «أنماط». أسماء المنتجات والشيفرة والروابط تبقى بصيغتها الأصلية عند الحاجة.

## الفصل بين الأنظمة

| النظام | السيناريو | حدود الوظيفة |
| --- | --- | --- |
| المساعد الخارجي العام | شرح أنماط وميزاتها وخططها وطريقة التسجيل للزائر | بلا تسجيل دخول أو أدوات تنفيذ؛ لا ينشئ حسابًا أو تذكرة ولا يطلب كلمات مرور أو بيانات دفع؛ يحيل إلى التسجيل أو الدعم عند الحاجة |
| مساعد الأعمال `/ai` | طلب بيانات أو تنفيذ إجراء على مهام المؤسسة ومشاريعها وتذكيراتها | أدوات المستخدم المسموح بها فقط؛ طلب المعلومات الناقصة قبل التنفيذ؛ عرض النتيجة الحقيقية |
| بوت الدعم العائم | استكشاف مشكلة استخدام أو اشتراك أو دفع | البحث في قاعدة المعرفة؛ لا يعدّل سجلات العمل؛ تصعيد من الواجهة بعد مراجعة الملخص والتأكيد |
| قاعدة المعرفة | البحث عن سياسات أو إجراءات | تُستخدم من المساعدين وفق الصلاحيات، مع التصريح بعدم توفر جواب موثوق |
| النماذج | توجيه النص والمرفقات إلى محول المزود | نجاح التوجيه البرمجي لا يثبت صلاحية المفتاح أو توفر النموذج لدى المزود |
| إكس | إدارة الحسابات والتصنيفات والإجراءات بحسب الصلاحيات والحصة | خدمة خارجية مستقلة؛ يجب عرض التعطل بوضوح؛ النشر الفعلي يحتاج اختبار تكامل بحساب اختبار |
| فيسبوك/إنستغرام/جيميل/يوتيوب | عرض حالة التكامل | غير متصلة في هذه الواجهة؛ لا حسابات تجريبية أو ادعاء أن النشر متاح |
| الموارد البشرية والمشاريع والاشتراكات والمحادثات | المسارات القائمة في الداشبورد | شملتها حزم الاختبارات الموجودة والتدقيق اللغوي؛ لم تُنفَّذ كل عملية على قاعدة بيانات حقيقية |

## سيناريو كل أداة للمساعد

جميع الأدوات التالية تعمل ضمن المستخدم والمؤسسة والصلاحيات. وجود الأداة لا يمنح صلاحية إضافية. وضع الدعم يقتصر على `query_knowledge_base`.

| الأداة | السيناريو والنتيجة المتوقعة |
| --- | --- |
| `list_my_tasks` | «اعرض مهامي» ← مهام المستخدم وفلاترها |
| `list_organization_tasks` | «اعرض مهام المؤسسة» ← مهام المؤسسة ضمن الصلاحيات |
| `get_task_details` | اختيار مهمة محددة ← تفاصيلها الحقيقية |
| `create_task` | تزويد بيانات المهمة اللازمة ← إنشاء واحد وإرجاع نتيجته |
| `add_task_stages` | تحديد المهمة والمراحل ← إضافة المراحل لهذه المهمة |
| `update_task` | تحديد المهمة والحقول المطلوبة ← تحديثها فقط |
| `delete_task` | طلب حذف مهمة محددة ← حذفها وفق الصلاحية وإظهار النتيجة |
| `list_projects` | «اعرض مشاريعي» ← قائمة المشاريع المتاحة |
| `get_project_details` | تحديد مشروع ← عرض تفاصيله |
| `create_project` | تزويد بيانات مشروع جديد ← إنشاء المشروع |
| `update_project` | تحديد المشروع والتغييرات ← تحديث المشروع المحدد |
| `list_employees` | البحث باسم موظف ← نتائج البحث لتحديد الشخص الصحيح |
| `get_employee_profile` | تحديد الموظف ← ملفه ضمن الصلاحيات |
| `get_my_analytics` | «لخّص أدائي» ← مؤشرات المستخدم |
| `get_company_analytics` | «لخّص أداء المؤسسة» ← المؤشرات المسموح بها |
| `list_my_reminders` | «اعرض تذكيراتي» ← تذكيرات المستخدم |
| `get_reminder_details` | اختيار تذكير ← تفاصيله |
| `create_reminder` | عنوان وموعد وتنبيهات ← إنشاء التذكير بعد استكمال البيانات الناقصة |
| `update_reminder` | تحديد تذكير وتعديلاته ← تحديثه |
| `delete_reminder` | طلب حذف تذكير محدد ← حذفه |
| `complete_reminder` | طلب إكمال تذكير ← تغيير حالته إلى مكتمل |
| `query_knowledge_base` | سؤال إجرائي ← البحث أولًا وبناء الإجابة على النتائج |
| `render_visualization` | بيانات فعلية جاهزة ← رسم يوضحها، دون اختلاق أرقام |
| `escalate_to_human` | طلب صريح لمساعدة بشرية في مساعد الأعمال ← إرجاع نتيجة طلب التواصل؛ لا تُنفّذ من بوت الدعم |

هذه مصفوفة سيناريوهات مستخرجة من تعريفات الأدوات، وليست ادعاءً باختبار كل معالج على قاعدة بيانات حقيقية.

## التحقق وحدوده

- نجحت 139 حالة في حزمة اختبارات الواجهة القائمة، و3 اختبارات لغة جديدة؛ و94 حالة في حزمة الخلفية ثم 11 حالة إضافية لتوجيه النماذج والمرفقات، وحالة لاستمرار حدود الدعم ولغة رسالة تعذّر المعالجة. المجموع 248 اختبار وحدة متميزًا ناجحًا، إضافة إلى 6 اختبارات متصفح ناجحة بالعربية والإنجليزية.
- نجح بناء الواجهة والخلفية؛ أعيد بناء الواجهة بعد استكمال القواميس النهائية.
- تمت معاينة لقطتي `audit-results/social-ar.png` و`audit-results/social-en.png`: اتجاه الواجهة والتبويبات ورسالة التعطل وزر المحاولة واضح باللغتين.
- فحص 632 ملف JavaScript/JSX: كانت 32 ترجمة عربية و412 تعريفًا إنجليزيًا ثابتًا ناقصة؛ أصبح عدد المفاتيح الثابتة الناقصة صفرًا باللغتين. لا يحكم هذا الفحص على كل نص يأتي من قاعدة البيانات أو استجابة خدمة خارجية.
- اختبارات حدود وضع الدعم، تسلسل رسائل الأدوات، الاستهلاك المتزامن، تكرار أسماء الأدوات، توجيه تسعة معرّفات نماذج، ومنع فقد الصورة/الصوت/الفيديو في التحويل البديل.
- اختبارات اللغة: تطابق متغيرات الاستيفاء، أوصاف النماذج، وتبديل اللغة.
- اختبار متصفح مع اعتراض الخدمات الخارجية: حالات التكامل والتعطل، المسار القديم، وعرض العربية مع الشيفرة. تشغيله: `npx playwright test --config playwright.audit.config.cjs` بعد بناء الواجهة.
- نجح اختبار المساعد الخارجي في نسخة الإنتاج بالعربية والإنجليزية: فتح المساعد، الإفصاح عن طبيعته، إرسال السؤال إلى `/api/public/ai/chat` بلا رمز دخول، عرض الإجابة، وإظهار مساري الدعم وإنشاء الحساب.
- إعادة التدقيق اللغوي: `node scripts/audit-dashboard-language.cjs language-audit.json`.

## ما يحتاج تحققًا متصلًا لاحقًا

- توفر مفاتيح المزودين والنماذج الفعلية، جودة الإجابات، المرفقات الحقيقية والفوترة.
- العمليات الكاملة للأدوات الأربع والعشرين على بيانات اختبار: الإنشاء والتعديل والحذف، تعدد المؤسسات، وتبديل الأدوار.
- إضافة/استيراد حساب إكس، فحص الحصة، تسجيل الدخول، والنشر أو الرد ثم التحقق من نتيجته بحساب اختبار.
- ملفات الدفع تتضمن رمز خصم تجريبيًا `BUYR|`، وصفحة الدعوة تتضمن بريدًا نموذجيًا. وُثّقت هذه النصوص في `language-audit.json`؛ يلزم ربطها ببيانات حقيقية بدل تحويلها إلى ترجمة توحي بأنها بيانات فعلية.
- مكوّن اختيار النماذج موجود لكنه غير مستخدم حاليًا في صفحة المساعد؛ الصفحة تعتمد التوجيه التلقائي. لا ينبغي عرضه للمستخدم باعتباره قائمة نماذج متاحة قبل التحقق من إعدادات المزودين.
